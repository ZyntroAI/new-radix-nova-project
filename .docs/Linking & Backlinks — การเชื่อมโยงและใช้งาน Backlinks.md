🔹 รูปแบบต่างๆ ของลิงก์
 
รูปแบบ ผลลัพธ์ ใช้เมื่อ 
 [[API]]  [[API]] ชื่อไฟล์เหมาะกับข้อความเลย 
`[[API เอกสารอ้างอิง API]]` [[API 
 [[Settings Tab + API Fetch#Endpoint Examples]]  ข้ามไปยังส่วนย่อยในไฟล์เดียว อ้างอิงหัวข้อเฉพาะเจาะจง 
 [[Settings Tab + API Fetch#^code-block-id]]  ข้ามไปยังบรรทัด/บล็อกเฉพาะ อ้างอิงโค้ดหรือเนื้อหาเฉพาะจุด 
 
💡 เคล็ดลับ: พิมพ์  [[  แล้วพิมพ์ตัวอักษรสองสามตัว — Obsidian จะแสดงรายการไฟล์ที่ตรงกันให้เลือกอัตโนมัติ ✅
 
 
 
↩️ Backlinks — ลิงก์ย้อนกลับคืออะไร?
 
Backlinks = รายการบันทึกที่มีลิงก์มาหาหน้านี้จากที่อื่น — เหมือนคนที่กล่าวถึงคุณในโพสต์อื่น
 
ถ้าในไฟล์ A เขียนว่า  ดูเพิ่มที่ [[B]]  → ที่ด้านล่างของไฟล์ B จะเห็นว่า ไฟล์ A อ้างถึง B ในส่วน Linked Mentions / Backlinks
 
✅ ประเภทของการอ้างอิง
 
ประเภท ความหมาย ตัวอย่าง 
🔗 Linked Mentions มีลิงก์ชี้มาที่หน้านี้โดยตรง  [[API]]  
📌 Unlinked Mentions มีชื่อหน้านี้ปรากฏในเนื้อหาแต่ ยังไม่ได้ทำเป็นลิงก์ เขียนว่า "API" ธรรมดา 
 
💡 Unlinked Mentions มีประโยชน์มาก: ช่วยคุณเห็นว่าคุณกำลังพูดถึงหัวข้อนี้อยู่ที่ไหนบ้าง — แล้วกดเปลี่ยนเป็นลิงก์ได้ทันที ✅
 
 
 
🛠️ วิธีใช้งาน Backlinks อย่างมีประสิทธิภาพ
 
✅ เปิดแผง Backlinks
 
- ที่ด้านข้างล่างของหน้าบันทึก → จะเห็นส่วน Linked Mentions และ Unlinked Mentions
- หรือกด  Ctrl/Cmd + Shift + I  เพื่อเปิดแผงด้านข้าง → เลือกแท็บ Backlinks
 
✅ ปรับการแสดงผล
 
ที่มุมขวาบนของแผง Backlinks มีเมนู ⚙️:
 
- ✅ Show unlinked mentions — แสดง/ซ่อนการกล่าวถึงที่ยังไม่เป็นลิงก์
- ✅ Show context — แสดงข้อความรอบๆ ที่กล่าวถึง (เห็นบริบทชัดขึ้น)
- ✅ Sort by: การเรียงลำดับ — เก่าสุด/ล่าสุด/ตามชื่อ
 
✅ ทำอะไรได้บ้างกับ Backlinks?
 
- 🔍 คลิก → กระโดดไปยังบันทึกนั้นทันที
- 🔗 กด + ถัดจาก Unlinked Mention → เปลี่ยนข้อความธรรมดาให้เป็นลิงก์
- 📝 แก้ไขลิงก์ → คลิกขวาที่ลิงก์ → แก้ไขหรือลบ
- 📂 เห็นภาพรวม → รู้ว่าหัวข้อนี้เชื่อมโยงกับอะไรบ้าง ไม่ใช่แค่ไฟล์โดดๆ
 
 
 
🎯 รูปแบบการทำงานที่แนะนำ
 
🔹 1. เมื่อสร้างบันทึกใหม่
 
plaintext
  
เขียนเนื้อหา → พิมพ์ `[[` เมื่อต้องการอ้างถึงสิ่งที่มีอยู่แล้ว
→ เลือกจากรายการ → บันทึก
→ ✅ ทันทีที่บันทึก — หน้าปลายทางจะเห็นลิงก์นี้ปรากฏใน Backlinks ทันที
 
 
🔹 2. เมื่อเปิดบันทึกเก่า
 
plaintext
  
ดูส่วน Backlinks ก่อน:
  → มีใครอ้างถึงหน้านี้บ้าง?
  → มีหัวข้อที่เกี่ยวข้องที่อาจต้องอ่านร่วมไหม?
  → มี Unlinked Mentions ไหมที่ควรเปลี่ยนเป็นลิงก์?
 
 
🔹 3. ใช้ควบคู่กับ MOC
 
MOC (Map of Content) คือดัชนีที่รวบรวมลิงก์ไปยังหัวข้อที่เกี่ยวข้อง — เมื่อคุณอัปเดตเนื้อหาในบันทึกใดบันทึกหนึ่ง → ทุกที่ที่ลิงก์มาหามันจะเชื่อมถึงกันโดยอัตโนมัติ

⚠️ ข้อแนะนำ & ข้อควรระวัง
 
✅ ควรทำ ❌ ไม่ควรทำ 
ใช้ชื่อไฟล์ที่ชัดเจนและไม่ซ้ำกัน สร้างลิงก์ไปยังไฟล์ที่ยังไม่มีอยู่จริงโดยไม่จำเป็น 
ลิงก์เมื่อเกี่ยวข้องกันจริงๆ ลิงก์ทุกคำที่ปรากฏ (เกะกะ อ่านยาก) 
ใช้ข้อความแสดงแทนเมื่อต้องการ `[[ชื่อไฟล์ ข้อความ]]` 
ตรวจสอบเป็นระยะๆ ว่าลิงก์ยังทำงานถูกต้อง ลบไฟล์ที่ยังมีคนอ้างถึงอยู่โดยไม่ย้าย/อัปเดตลิงก์ 
 
💡 เมื่อเปลี่ยนชื่อไฟล์: Obsidian จะถามว่าให้อัปเดตลิงก์ทั้งหมดที่ชี้มาหาไฟล์นี้หรือไม่ — ตอบ ✅ อัปเดตทั้งหมด เสมอ เพื่อไม่ให้ลิงก์พัง ✅

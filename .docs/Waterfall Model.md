🌱 Waterfall Model
 
🎯 Summary
 
Waterfall Model คือแบบจำลองการพัฒนาซอฟต์แวร์แบบดั้งเดิมที่ทำงานเป็นขั้นเป็นตอน เรียงลำดับจากบนลงล่างเหมือนน้ำตก — แต่ละขั้นตอนต้องเสร็จสมบูรณ์ก่อนจะก้าวไปขั้นถัดไป และโดยทั่วไปไม่ย้อนกลับได้ง่าย
 
🧠 Core Stages
 
1. ความต้องการ (Requirements) — รวบรวมและบันทึกสิ่งที่ต้องการทั้งหมด
2. การออกแบบ (Design) — วางแผนโครงสร้างระบบและเทคนิค
3. การนำไปใช้ (Implementation) — เขียนโค้ดและสร้างระบบ
4. การทดสอบ (Verification) — ตรวจสอบว่าตรงตามความต้องการหรือไม่
5. การติดตั้ง (Deployment) — ส่งมอบและติดตั้งระบบจริง
6. การบำรุงรักษา (Maintenance) — ดูแลและแก้ไขหลังส่งมอบ
 
✅ ข้อดี
 
- 🟢 โครงสร้างชัดเจน เข้าใจง่าย
- 🟢 วางแผนและกำหนดเวลา/งบประมาณได้แน่นอน
- 🟢 เน้นเอกสารครบถ้วน — ง่ายต่อการส่งต่อ
- 🟢 เหมาะกับโครงการที่ความต้องการคงที่และไม่เปลี่ยนแปลงบ่อย
 
⚠️ ข้อจำกัด
 
- 🔴 ย้อนกลับแก้ไขยากและมีค่าใช้จ่ายสูง
- 🔴 ไม่รองรับการเปลี่ยนแปลงความต้องการ
- 🔴 เห็นผลงานจริงช้า — รอจนสิ้นสุดกระบวนการ
- 🔴 ความเสี่ยงสูงหากความต้องการเปลี่ยนในภายหลัง
 
💡 เปรียบเทียบกับ Agile

ลักษณะ เส้นตรง ทีละขั้น วนซ้ำ รอบสั้นๆ 
การเปลี่ยนแปลง หลีกเลี่ยง ยอมรับยาก คาดหวัง ปรับตัวได้ตลอดเวลา 
ผลลัพธ์ เห็นชิ้นเดียวตอนจบ เห็นบางส่วนในทุกๆ รอบ 
ความต้องการ ต้องระบุให้ครบตั้งแต่ต้น สามารถปรับระหว่างทางได้ 
 
💡 Key Insight
 
Waterfall ไม่ได้ "ล้าสมัย" แต่เหมาะกับ บริบทที่ความต้องการคงที่และสามารถระบุได้ชัดเจนตั้งแต่ต้น เช่น โครงการขนาดใหญ่ภาครัฐ หรือระบบวิศวกรรมที่มีกฎระเบียบเข้มงวด สิ่งสำคัญคือเลือกใช้ให้ถูกกับปัญหา ไม่ใช่ใช้ทุกที่

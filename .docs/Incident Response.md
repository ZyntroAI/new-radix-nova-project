🚨 Incident Response — คู่มือการตอบสนองต่อเหตุการณ์ความมั่นคง
 
Incident Readiness = มีแผนชัดเจนพร้อมใช้งานทันทีเมื่อตรวจพบการรั่วไหลหรือเหตุการณ์ผิดปกติ
 
 
 
📋 Lifecycle — 7 ขั้นตอนมาตรฐาน
 
1. 📚 Preparation — เตรียมความพร้อม
 
- กำหนดทีมและบทบาท: ผู้ประสานงาน, ผู้สืบสวน, ผู้สื่อสาร, ผู้จัดการระบบ
- จัดทำเอกสาร: รายการติดต่อฉุกเฉิน, ขั้นตอนการปฏิบัติ, แผนสำรอง
- ฝึกซ้อมเป็นประจำ — ทดสอบแผนอย่างน้อยปีละ 1–2 ครั้ง
- ติดตั้งระบบตรวจจับและเฝ้าดู: Log, Monitoring, Alerting — [[Monitoring & Observability]]
 
2. 🔍 Detection & Analysis — ตรวจพบและวิเคราะห์
 
- รับแจ้ง/ตรวจพบสัญญาณผิดปกติ: Alert, การแจ้งเตือนจากทีม, รายงานจากผู้ใช้
- จำแนกระดับความรุนแรง:
- P1 — Critical: ระบบหลังล่ม/ข้อมูลสำคัญรั่ว → ทันที
- P2 — High: บางส่วนเสียหาย/การทำงานผิดปกติ → ภายใน 1 ชม.
- P3 — Medium: ความเสี่ยงแต่ยังไม่มีความเสียหาย → ภายใน 4 ชม.
- P4 — Low: ปัญหาเล็กน้อย → ปกติทำงาน
- ยืนยันความถูกต้อง: ไม่ใช่ false positive
- บันทึกเวลาและรายละเอียดทุกอย่าง
 
3. 🛡️ Containment — ควบคุมสถานการณ์ ⚡ ทำก่อน!
 
เป้าหมาย: หยุดความเสียหายไม่ให้แพร่กระจายต่อ — ก่อนจะแก้ไข
 
- ระยะสั้น: ปิดช่องโหว่, ถอดระบบที่ติดออกจากเครือข่าย, บล็อก IP ที่น่าสงสัย, เปลี่ยนรหัสผ่าน
- ระยะยาว: รักษาให้ระบบหลักทำงานต่อได้ด้วยแผนสำรอง
- ⚠️ สำคัญมาก: อย่าลบ/แก้ไขหลักฐาน — บันทึกทุกอย่างก่อนแก้ไข
 
4. 🧹 Eradication — กำจัดสาเหตุ
 
- ค้นหาวิธีการที่ผู้บุกรุกใช้เข้ามา
- ปิดช่องโหว่ทั้งหมด
- ลบมัลแวร์/บัญชีผู้ไม่หวังดี/Backdoor
- ตรวจสอบระบบที่เกี่ยวข้องทั้งหมด — ตรวจหาร่องรอยการแทรกซ้อนเพิ่มเติม
 
5. ♻️ Recovery — กู้คืนและกลับมาใช้งาน
 
- ตรวจสอบความสะอาดและความปลอดภัยก่อนเปิดใช้
- กู้คืนข้อมูลจากสำเนาที่ปลอดภัย (ก่อนเกิดเหตุ)
- ทดสอบการทำงานอย่างละเอียด
- ค่อยๆ เปิดบริการทีละส่วน — เริ่มจากส่วนสำคัญก่อน
- เฝ้าดูอย่างใกล้ชิดเป็นเวลาอย่างน้อย 72 ชม.
 
6. 📝 Post-Incident Activity — เรียนรู้และปรับปรุง
 
- ทำทันทีหลังเหตุการณ์สงบ: ประชุมทบทวน
- ตอบคำถามสำคัญ:
- เกิดอะไรขึ้น และเมื่อไหร่?
- ใครทำอะไร และทำไม?
- เรารู้ได้อย่างไรว่าเกิดขึ้น?
- เราจะป้องกันไม่ให้เกิดซ้ำได้อย่างไร?
- ปรับปรุงนโยบาย, ระบบ, ขั้นตอน
- อัปเดตแผนรับมือเหตุการณ์
 
7. 📢 Communication — การสื่อสาร
 
- กำหนดผู้พูดคนเดียว — ไม่ให้ทุกคนตอบคำถามภายนอก
- แจ้งความคืบหน้าให้ทีมและผู้มีส่วนได้ส่วนเสียทราบเป็นระยะ
- แจ้งหน่วยงานที่เกี่ยวข้องตามกฎหมายหากมีการรั่วไหลข้อมูลส่วนบุคคล
 
 
 
📊 Severity Levels & Response SLA
 
ระดับ สี เวลาตอบสนอง ตัวอย่าง 
P1 — Critical 🔴 แดง ทันที ข้อมูลลูกค้ารั่ว, ระบบชำระเงินล่ม 
P2 — High 🟠 ส้ม ภายใน 1 ชม. บริการหลักทำงานผิดบางส่วน 
P3 — Medium 🟡 เหลือง ภายใน 4 ชม. การแจ้งเตือนผิดปกติ แต่ยังไม่มีผลกระทบ 
P4 — Low 🟢 เขียว ถัดไป ปรับปรุงความปลอดภัยเล็กน้อย

⚠️ Golden Rules — กฎทอง
 
1. ไม่ต้องตกใจ — มีแผนไว้แล้ว ทำตามแผน
2. บันทึกทุกอย่าง — เวลา, การกระทำ, ผลลัพธ์
3. ควบคุมก่อน — กำจัดทีหลัง: หยุดความเสียหายก่อนเสมอ
4. อย่าปิดบัง — แจ้งให้ทราบเร็วที่สุดเท่าที่เป็นไปได้
5. เรียนรู้จากทุกครั้ง — ทบทวนเพื่อไม่ให้เกิดซ้ำ

📢 Data Breach Notification Procedure — ขั้นตอนแจ้งกรณีข้อมูลรั่วไหล
 
เมื่อเกิดการรั่วไหลของข้อมูลส่วนบุคคลหรือข้อมูลสำคัญ — กฎหมายกำหนดเวลาที่ชัดเจน ความล่าช้าอาจมีค่าปรับสูงมาก ⚠️
 
 
 
⚖️ กฎหมายที่เกี่ยวข้อง (ประเทศไทย)
 
กฎหมาย ข้อกำหนดสำคัญ กำหนดเวลาแจ้ง ค่าปรับสูงสุด 
พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 (PDPA) แจ้งสำนักงานคณะกรรมการคุ้มครองข้อมูลส่วนบุคคล และแจ้งเจ้าของข้อมูลหากมีความเสี่ยงสูง ภายใน 72 ชั่วโมง นับแต่ทราบเหตุการณ์ ไม่เกิน 5 ล้านบาท 
พ.ร.บ. การรักษาความมั่นคงปลอดภัยไซเบอร์ พ.ศ. 2562 แจ้งหน่วยงานตามระดับความรุนแรงของเหตุคุกคามทางไซเบอร์ ทันที / ภายใน 24 ชม. ตามประเภทเหตุการณ์ ไม่เกิน 1 ล้านบาท 
 
 
 
🔑 เมื่อไหร่ต้องแจ้ง?
 
✅ เกณฑ์การประเมิน — ตอบ 3 คำถาม
 
plaintext
  
1️⃣ ข้อมูลที่รั่ว = ข้อมูลส่วนบุคคลหรือข้อมูลสำคัญหรือไม่?
   → ชื่อ, เบอร์, อีเมล, เลขบัตรประชาชน, ข้อมูลการเงิน, รหัสผ่าน

2️⃣ มีความเสี่ยงต่อสิทธิและเสรีภาพของบุคคลหรือไม่?
   → ขโมยเอกลักษณ์, การฉ้อโกง, ความเสียหายทางการเงิน

3️⃣ มีความเป็นไปได้ของความเสียหายหรือไม่?
   → แน่นอน → ต้องแจ้ง
   → ไม่น่าจะเกิดขึ้น → บันทึกเหตุผลไว้เป็นลายลักษณ์อักษร
 
 
❌ ไม่ต้องแจ้ง
 
- ข้อมูลที่ไม่ใช่ข้อมูลส่วนบุคคล หรือไม่สามารถระบุตัวบุคคลได้
- ผลกระทบมีความเสี่ยงต่ำมาก
- มีการปกป้องที่เหมาะสม (เข้ารหัส, ทำให้ไม่สามารถอ่านได้) — แต่ต้องบันทึกเหตุผลไว้เสมอ ✅
 
 
 
📋 ขั้นตอนการปฏิบัติ — 7 ขั้นตอนหลัก
 
plaintext
  
0️⃣ ยืนยันเหตุการณ์ → ประเมินความรุนแรง
       ⬇️
1️⃣ จัดตั้งทีมเฉพาะกิจ
       ⬇️
2️⃣ ประเมินขอบเขตและผลกระทบ
       ⬇️
3️⃣ ตัดสินใจ: แจ้งหรือไม่แจ้ง — ทำไม?
       ⬇️
4️⃣ เตรียมหนังสือแจ้ง
       ⬇️
5️⃣ ส่งแจ้งหน่วยงาน + แจ้งเจ้าของข้อมูล
       ⬇️
6️⃣ ติดตามและรายงานความคืบหน้า
       ⬇️
7️⃣ บันทึกและจัดเก็บเอกสาร
 
 
 
 
⏰ ขั้นที่ 0: ยืนยันและประเมิน — ภายใน 4 ชั่วโมงแรก
 
✅ ตรวจสอบข้อมูลพื้นฐาน
 
plaintext
  
📋 แบบประเมินเบื้องต้น — การรั่วไหลข้อมูล

1. วันที่และเวลาที่ทราบเหตุ: ________________________
2. วันที่และเวลาที่เกิดเหตุประมาณ: ___________________
3. ลักษณะข้อมูลที่ได้รับผลกระทบ:
   [ ] ชื่อ-นามสกุล  [ ] เลขบัตรประจำตัวประชาชน
   [ ] ที่อยู่  [ ] เบอร์โทร / อีเมล
   [ ] ข้อมูลการเงิน / บัญชีธนาคาร / บัตรเครดิต
   [ ] รหัสผ่าน / บัญชีผู้ใช้  [ ] ข้อมูลละเอียดอ่อนอื่นๆ
   ประเภท: ________________________________________

4. ปริมาณ/จำนวนผู้ได้รับผลกระทบ: ______ คน / บันทึก

5. สาเหตุและวิธีการ:
   [ ] เจตนาทุจริต/แฮ็ก  [ ] ข้อผิดพลาดของพนักงาน
   [ ] สูญหายอุปกรณ์  [ ] ผู้รับจ้าง/บุคคลภายนอก
   [ ] อื่นๆ: ____________________________________

6. ระดับความเสี่ยง:
   🔴 สูง — ต้องแจ้งทันที
   🟡 ปานกลาง — ประเมินเพิ่มเติม
   🟢 ต่ำ — บันทึกไว้เฝ้าติดตาม
 
 
⚠️ ภายใน 72 ชั่วโมงนับแต่ทราบเหตุ — ต้องส่งหนังสือแจ้งออกไปแล้ว หากตัดสินใจว่าต้องแจ้ง ✅
 
 
 
👥 ขั้นที่ 1: จัดตั้งทีมเฉพาะกิจ
 
บทบาท หน้าที่ บุคคลที่รับผิดชอบ 
🎯 ผู้อำนวยการ ตัดสินใจสูงสุด รับผิดชอบการแจ้ง ผู้บริหารระดับสูง / ผู้รับมอบหมาย 
⚖️ ทีมกฎหมาย ตรวจสอบข้อความ ประเมินความรับผิดชอบ ทีมกฎหมายภายใน / ที่ปรึกษากฎหมาย 
🔐 ทีมความมั่นคง รายงานข้อเท็จจริง ขอบเขต สาเหตุ CISO / ทีม SecOps 
📣 ทีมสื่อสาร จัดการข้อความภายในและภายนอก ทีมประชาสัมพันธ์ / ผู้บริหาร 
📝 เลขานุการ จัดเก็บเอกสาร บันทึกกระบวนการ ผู้ประสานงาน 
 
 
 
🔍 ขั้นที่ 2: ประเมินขอบเขตและผลกระทบอย่างละเอียด
 
✅ คำถามที่ต้องได้คำตอบก่อนแจ้ง
 
- ข้อมูลอะไรรั่วบ้าง? — รายการชัดเจน
- มีใครเข้าถึง/นำไปใช้ประโยชน์หรือไม่?
- ข้อมูลถูกเปิดเผย ทิ้ง หรือสูญหาย?
- เราได้ทำอะไรเพื่อหยุดความเสียหายแล้วบ้าง?
- มีมาตรการอะไรเพื่อป้องกันในอนาคต?
 
💡 ไม่ต้องรอจนกว่าสืบสวนจบ 100% เพื่อเริ่มกระบวนการแจ้ง — แจ้งสิ่งที่ทราบก่อน แล้วส่งข้อมูลเพิ่มเติมทีหลังได้ ✅
 
 
 
✅ ❌ ขั้นที่ 3: ตัดสินใจ — แจ้งหรือไม่แจ้ง?
 
✅ ต้องแจ้งสำนักงาน PDPA เมื่อ
 
- มีความเป็นไปได้ที่การรั่วไหลจะก่อให้เกิด ความเสี่ยงต่อสิทธิและเสรีภาพ ของบุคคล
- โดยเฉพาะ: ข้อมูลละเอียดอ่อน, ข้อมูลจำนวนมาก, ผลกระทบรุนแรง
 
✅ ต้องแจ้งเจ้าของข้อมูลโดยตรงเมื่อ
 
- มีความเสี่ยง สูงมาก ต่อสิทธิและเสรีภาพของบุคคล
- แจ้งด้วยวิธีที่เหมาะสม: จดหมาย, อีเมล, ประกาศบนเว็บไซต์
- บอก: เกิดอะไรขึ้น, ข้อมูลอะไรได้รับผลกระทบ, สิ่งที่ต้องระวัง และช่องทางติดต่อ
 
✅ บันทึกเหตุผลเมื่อตัดสินใจว่า "ไม่ต้องแจ้ง"
 
ไม่แจ้ง = ต้องอธิบายได้ว่า ทำไมไม่มีความเสี่ยง — บันทึกเป็นลายลักษณ์อักษรทุกครั้ง ✅
 
 
 
✉️ ขั้นที่ 4: เตรียมหนังสือแจ้ง
 
📄 ข้อมูลที่ต้องระบุในหนังสือแจ้ง
 
plaintext
  
📝 หนังสือแจ้งการรั่วไหลของข้อมูลส่วนบุคคล

1. ชื่อและที่อยู่ของผู้ควบคุมข้อมูลส่วนบุคคล
   ____________________________________________________

2. วันที่และเวลาที่ทราบเหตุการณ์: ____________________

3. ลักษณะและสาเหตุของการรั่วไหลข้อมูลส่วนบุคคล:
   ____________________________________________________

4. ประเภทและขอบเขตของข้อมูลส่วนบุคคลที่ได้รับผลกระทบ:
   • ประเภทข้อมูล: __________________________________
   • จำนวนผู้ได้รับผลกระทบ: _________________________

5. ผลกระทบที่อาจเกิดขึ้นจากการรั่วไหลของข้อมูลส่วนบุคคล:
   ____________________________________________________

6. มาตรการที่ได้ดำเนินการเพื่อจัดการกับการรั่วไหล:
   ____________________________________________________

7. ข้อมูลสำหรับการติดต่อ:
   ชื่อผู้ประสานงาน: _______________________________
   เบอร์ติดต่อ: ____________________________________
   อีเมล: _________________________________________
 
 
⚠️ ข้อความต้องชัดเจน จริง ไม่ปกปิดข้อเท็จจริง — ไม่ต้องสวยหรู แต่ต้องครบถ้วนและถูกต้อง ✅
 
 
 
🚀 ขั้นที่ 5: ส่งแจ้งหน่วยงาน + แจ้งเจ้าของข้อมูล
 
🔹 ช่องทางแจ้งสำนักงาน PDPA
 
- 📧 อีเมล: breach@opdc.go.th
- 🌐 เว็บไซต์: www.opdc.go.th → แบบฟอร์มแจ้งเหตุการรั่วไหลข้อมูลส่วนบุคคล
- 📝 เอกสารแนบ: หนังสือแจ้ง + แบบประเมิน + เอกสารอื่นๆ ที่เกี่ยวข้อง
 
✅ เก็บหลักฐานการส่ง — วันที่ เวลา และหลักฐานการยืนยันการรับ ✅
 
🔹 แจ้งเจ้าของข้อมูล
 
- 📧 อีเมล — ถ้ามีอีเมล
- 📍 จดหมาย — กรณีสำคัญหรือไม่มีช่องทางอื่น
- 🌐 ประกาศสาธารณะ — เมื่อไม่สามารถติดต่อทีละคนได้ หรือผลกระทบกว้างขวาง
 
✅ ตัวอย่างข้อความแจ้งผู้ใช้
 
เรื่อง: แจ้งเหตุการณ์ความผิดปกติเกี่ยวกับข้อมูลส่วนบุคคล
 
เรียน ท่านผู้ใช้บริการ
 
ขอแจ้งว่าเมื่อวันที่ [วันที่] เราพบเหตุการณ์ [รายละเอียดโดยย่อ] ซึ่งอาจส่งผลให้ข้อมูลประเภท [ประเภทข้อมูล] ของท่านได้รับผลกระทบ
 
📌 สิ่งที่ท่านควรทราบและปฏิบัติ:
• ระมัดระวังการใช้ข้อมูลส่วนตัว หากพบความผิดปกติ โปรดแจ้งเราโดยทันที
• ขณะนี้เราได้ดำเนินการ [มาตรการที่ทำไปแล้ว] เพื่อควบคุมสถานการณ์
• เราจะเฝ้าติดตามและแจ้งความคืบหน้าให้ทราบต่อไป
 
📞 หากมีข้อสงสัย ติดต่อ: [ช่องทางติดต่อ]
ขอแสดงความนับถือ
ทีมงาน [ชื่อองค์กร]
 
 
 
📈 ขั้นที่ 6: ติดตามและรายงานความคืบหน้า
 
- ✅ ส่งข้อมูลเพิ่มเติมเมื่อสืบสวนได้ข้อเท็จจริงเพิ่ม
- ✅ แจ้งความคืบหน้าให้ผู้บริหารทราบเป็นระยะ
- ✅ บันทึกทุกการสื่อสาร — อีเมล, จดหมาย, โทรศัพท์
- ✅ รายงานผลสรุปเมื่อสถานการณ์กลับสู่ภาวะปกติ
 
 
 
📂 ขั้นที่ 7: จัดเก็บเอกสาร
 
⚠️ เก็บเอกสารทั้งหมดไว้อย่างน้อย 5 ปี นับแต่วันที่ดำเนินการแล้วเสร็จ ✅
 
รายการเอกสาร ระยะเวลาเก็บรักษา 
แบบประเมินเบื้องต้น ไม่น้อยกว่า 5 ปี 
หนังสือแจ้งและหลักฐานการส่ง ไม่น้อยกว่า 5 ปี 
บันทึกการสื่อสารและการตัดสินใจ ไม่น้อยกว่า 5 ปี 
รายงานสรุปเหตุการณ์และมาตรการแก้ไข ไม่น้อยกว่า 5 ปี 
หลักฐานการแจ้งเจ้าของข้อมูล ไม่น้อยกว่า 5 ปี 
 
 
 
⚠️ สิ่งที่ห้ามทำในสถานการณ์นี้
 
❌ ห้ามทำ เหตุผล 
❌ ปกปิดหรือล่าช้าแจ้ง อาจถูกปรับและมีความรับผิดทางกฎหมายเพิ่มขึ้น 
❌ ให้ข้อมูลเท็จหรือบิดเบือนความจริง ทำลายความน่าเชื่อถือและอาจผิดกฎหมายอาญา 
❌ แจ้งข่าวภายนอกก่อนกระบวนการเสร็จสิ้น ข้อมูลไม่ครบถ้วน อาจทำให้สถานการณ์แย่ลง 
❌ บังคับให้พนักงานรับผิดแทนองค์กร ความรับผิดเป็นของนิติบุคคลตามกฎหมาย 
❌ ลบ/แก้ไขหลักฐาน อาจเป็นอุปสรรคต่อการสืบสวนและกระบวนการกฎหมาย 
 
 
 
✅ Checklist — พร้อมรับมือการรั่วไหลข้อมูลไหม?
 
มีเอกสารกระบวนการแจ้งเหตุที่เป็นลายลักษณ์อักษร ✅
รู้ช่องทางและผู้รับผิดชอบในการแจ้งสำนักงาน PDPA ✅
มีแบบประเมินความจำเป็นในการแจ้ง ✅
มีตัวอย่างหนังสือแจ้งและข้อความแจ้งผู้ใช้ ✅
ทีมที่เกี่ยวข้องรู้บทบาทและหน้าที่ของตน ✅
มีนโยบายการจัดเก็บเอกสารหลักฐาน ✅
ได้ระบุผู้รับผิดชอบสูงสุดไว้อย่างชัดเจน ✅
ทบทวนและซ้อมกระบวนการนี้อย่างน้อยปีละ 1 ครั้ง ✅
